## Review Focus

- **Ticker not resolvable / outside VN30 coverage** — spec §4.7 defines a `universe_tier` fail-closed gate already implemented in the pipeline; the skill must not attempt to paper over a `not_found`/low-coverage warning from `run_analysis`/`get_snapshot` with a confident-sounding answer. Task 1's skill body states this explicitly and Task 2's manual test exercises it with a bogus ticker.
- **User asks a leading/biased question** ("HPG chắc chắn tăng đúng không?") — spec §4.5 says the answer must not change based on how the question is phrased. The skill body must instruct Hermes to always ground the verdict in the tool's own `signal`/`data`, not the user's framing, and to never adopt the word "chắc chắn". Task 1 covers this in the skill body; Task 2's manual test includes exactly this phrasing.
- **`/chay` vs. plain-language "phân tích X" vs. quick-look "X hôm nay sao rồi?"** must map to different `depth` values per spec §4.3 (`full` vs `quick`) — a skill that always calls `run_analysis` with the same depth silently breaks the spec's on-demand vs. quick-look distinction. Task 1's routing table encodes this; Task 2 tests both phrasings.
- **`explain_run`/history-style questions must NOT re-trigger the pipeline** — spec §4.3 explicitly lists "vì sao stop-loss đặt ở đó?" as a read-from-saved-run question, not a new `run_analysis` call. The skill's routing table must route explanation questions to `explain_run`/`get_snapshot`/`query_history` and never to `run_analysis`. Task 1 encodes this; Task 2 tests it.
- **Empty/error results from a tool (`status: "not_found"`, `status: "error"`, empty `warnings`-bearing envelope)** must be relayed to the user as-is, not narrated over — this is spec §2's fail-closed principle applied to the chat surface. The skill body must say: never invent an answer when a tool returns `not_found` or an error status; quote the tool's own `warnings` back to the user. Task 1 states this; Task 2's bogus-ticker test exercises it.
